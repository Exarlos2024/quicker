QuickerLite 界面设计方案

针对现有 WPF 面板的一次完整视觉与交互重构。目标不是换一套皮肤，而是让「唤出 → 选择 → 执行」这条主路径在键盘上、在第一次使用时、在低质量屏幕上都能成立。

版本 v1 2026-09-13 浅色主题 对象：PanelWindow / SettingsWindow / ImportWindow

01设计目标与五条原则

这个界面不是「一个窗口」，是「一次键盘动作的延伸」。它的绝大多数出现只持续两秒，用户看完就忘。所有决策都从这一点出发。

五条原则

  1. 弹出即走。面板是瞬态浮层，不是文档窗口。它不该有标题栏、不该有「确定/取消」、不该要求用户先理解布局再动手。打开后最该被看到的，是「按哪里能跑起来」。
  2. 键盘优先。任何一个用鼠标能完成的动作，都必须有一条键盘走法。这是启动器的存在意义——如果还要摸鼠标，用户不如直接去点任务栏。
  3. 几何恒定。面板的尺寸和格子位置不能随内容多少而变化。肌肉记忆建立在「第 3 个格子永远在这个位置」上，位置一变，记忆就废了。
  4. 状态可辨。任意两个状态之间的差异必须一眼可辨，不能只差一点亮度。「我到底选中了没有」这种犹豫本身就是缺陷。
  5. 颜色让位。界面的颜色预算留给用户自己的图标。面板本体只使用一个中性色阶加一个强调色，把彩度全部让出去。

与现状的关系

现有实现的功能骨架是完整的——热键、多页、搜索排序、拖拽、多选都在。这次重构不动任何数据结构和业务逻辑，只改视觉层与交互层：格子模板、腰栏、令牌、键盘处理。所有改动都可以分批上线，每批独立可用。

空状态与无结果

两者是不同场景，不能共用一套文案：

  • 面板全空：一个简笔插图 + 主文案「面板还是空的」+ 两个并排按钮「扫描开始菜单」「从文件添加」。现在只有一行灰字，用户看完仍然不知道怎么开始。
  • 搜索无结果：保留现有的「没有匹配「xxx」的条目」，下面补一个可点动作「添加「xxx」到面板」——搜索失败的时刻，恰好是用户最想添加东西的时刻。这个入口现在完全没有。

08无障碍与兼容

  • 对比度。所有正文文字 ≥ 4.5:1，大字与图形 ≥ 3:1。禁用态不参与达标要求，但必须仍可辨认轮廓。审计出的两处不达标色值已全部替换。
  • 点击目标。格子 84 × 92、页签高 26、图标按钮 23 × 23。除图标按钮外全部超过 32 × 32 的建议下限；图标按钮靠加大内边距到 23px 并保持 10px 间隔来补偿。
  • 不依赖颜色单独传达信息。选中除了底色变化，还有勾选角标；焦点除了底色，还有描边环。色觉障碍用户同样能区分。
  • 减少动画。检测 SystemParameters.ClientAreaAnimation，为 false 时全部过渡时长置 0。
  • 高对比度模式。检测 SystemParameters.HighContrast，为 true 时改用系统 SystemColors，放弃自定义令牌——这是 Windows 平台的通行做法，不要试图用自定义色值硬扛。
  • DPI。沿用现有的物理像素定位方案（PositionAtCursor）。新增的固定尺寸需要按 dpiX / 96 换算，否则 150% 缩放下面板会超出预期宽度。

09WPF 落地映射

这一节是给实现看的。所有改动都限于视图层，不动 ConfigStore、PageResolver、SearchRanker 等业务代码。

令牌资源字典

新建 Themes/Tokens.xaml，在 App.xaml 里合并。当前三个窗口各自硬编码色值，合并后统一引用。现有的 PanelWindow.Resources 里那几个 Style 也一并搬过去，让设置窗和导入窗复用同一套控件外观。

建议的资源粒度：

  • Color 与配套的 SolidColorBrush 各一份（Brush 全部 x:Shared="True" 或代码里 Freeze()，避免每次 hover 分配对象）
  • Thickness：间距序列、面板内边距
  • Double：圆角、尺寸、过渡时长
  • Style：ActionTileStyle / FlatButtonStyle / PageTabStyle / IconButtonStyle

窗口合成与阴影

不要为了阴影直接打开 AllowsTransparency="True"。在 WPF 里这个属性会让整个窗口退回软件渲染，面板的绘制开销明显上升，而这个面板是常驻热键唤出的高频窗口。推荐做法是保持 AllowsTransparency="False"，通过 DWM 拿系统投影：把 DwmExtendFrameIntoClientArea 的边距设为 1px，DWM 就会为无边框窗口绘制标准投影；圆角继续用现有的 DWMWA_WINDOW_CORNER_PREFERENCE，Win10 上自然退化为直角加 1px 描边。这样既有投影，又保留硬件加速。

格子模板改造

现有模板已经是「Grid 包住 Button + 一层选中高亮 Border」的结构，这个结构是对的，扩展即可：

  • 加一层 Border 作为图标容器（44 × 44，圆角 11，底 #F2F3F5），图标放进去，绘制区 32 × 32
  • 加一个 TextBlock 做数字角标，绑视图模型上的新属性 IndexText（前 9 项返回 "1"…"9"，其余返回空字符串）
  • 再加一层 Border 做键盘焦点环，IsHitTestVisible="False"，绑 FocusRingVisibility——和现有 SelectionVisibility 完全同构
  • 名称 TextBlock 去掉 TextWrapping，改为 TextTrimming="CharacterEllipsis" + 单行
  • ItemWidth/ItemHeight 从 92/96 改为 92/100

腰栏页签

好消息是这部分代码已经存在：跨页拖拽时生成的 PageDropChips 就是文字胶囊页签。把 RenderPageChips 的渲染逻辑抽成一个共用方法，腰栏平时渲染页签、拖拽时渲染放置区，两者共用同一套 Border + TextBlock 构造代码。现有的 PageDots 与 PageNameButton 可以整体删除。

固定尺寸

ApplyColumns 里把 SizeToContent 从 Height 改为 Manual，高度按 3 × 100 + 48 + 44 + 4 算成常量。行数可以做成设置项，但同一台机器上必须固定。

键盘焦点

新增 _focusIndex 与视图模型上的 IsFocusCursor，由 OnWindowPreviewKeyDown 处理方向键。注意两个坑：一是在搜索框有内容时，左右方向键应该留给文本编辑（用 SearchBox.IsKeyboardFocusWithin 判断）；二是焦点移动后要 ScrollIntoView，否则移到可视区外就没有反馈。

10分阶段实施

四批，每批独立可发布、可回滚。前两批只改视觉，风险最低；键盘交互单独一批，因为它要动 PreviewKeyDown 的分支逻辑，回归面最大。

实施结果（四批已全部落地）

P0–P3 已按上表顺序实现完毕，代码在当前工作区。与计划的偏差只有一处：令牌的唯一来源放在 C# 而不是 XAML——UI/DesignTokens.cs 定义 Palette 与 Metrics 两个静态类，Themes/Tokens.xaml 里的样式再通过 {x:Static ui:Palette.Xxx} 引用。这样颜色和尺寸只有一份定义，XAML 与 C# 不会各写一遍然后悄悄漂移；代价是 XAML 里要引入 xmlns:ui。

明确的取舍

  • 不做深色主题。Windows 的深色模式需要整套色阶重算与对比度复验，工作量约等于再做一遍。等浅色版稳定后单独立项。
  • 不做自定义换肤。面板的颜色预算已经让给用户图标了，再加主题变量只会让「图标与背景打架」的概率变高。
  • 不做圆角自绘。继续依赖 DWM，Win10 上就是直角。为一个已经停止支持的系统写自绘窗口区域，性价比不成立。
  • 不改 WrapPanel。换成 UniformGrid 或自绘面板能省一点测量开销，但会破坏现有的拖拽落点计算（TileReorder 依赖真实的容器边界）。性能不是当前的瓶颈。
