# QuickerLite

一个 Windows 快捷启动面板，复刻 [Quicker](https://getquicker.net/) 的核心体验：
**按下热键 → 弹出网格面板 → 点一下启动 → 面板自动消失。**

技术栈：C# + WPF + .NET 8，零第三方依赖（托盘用 WinForms 自带的 `NotifyIcon`，
配置用内置的 `System.Text.Json`）。

[![CI](https://github.com/Exarlos2024/quicker/actions/workflows/ci.yml/badge.svg)](https://github.com/Exarlos2024/quicker/actions/workflows/ci.yml)

## 下载

最新版本见 [Releases](https://github.com/Exarlos2024/quicker/releases/latest)：
下载 `QuickerLite-<版本>-win-x64.zip`，解压后直接双击 `QuickerLite.exe` 即可 ——
自包含单文件版，**目标机器上不需要装 .NET 运行时**。

每次给 `v*` 标签（如 `git tag v1.0 && git push origin v1.0`）推上去，
GitHub Actions 会自动构建、跑回归用例、并把带 SHA256 校验文件的压缩包挂到 Release 上。

## 现在能做什么

**核心**
- **单击 `Ctrl` 唤出 / 隐藏**（Quicker 的招牌操作，靠低级键盘钩子实现）
- 全局热键 `Ctrl+Alt+Q` 唤出 / 隐藏（可在设置里改）
- **单击鼠标中键唤出 / 隐藏**
- 网格面板，点格子直接启动程序 / 打开文件夹 / 打开文件 / 打开网址
- 面板跟随鼠标弹出，自动避开屏幕边缘
- **键盘全流程**：方向键移动焦点、`Enter` 运行焦点格、`Ctrl+1`…`Ctrl+9` 直选前 9 格、
  `Ctrl+F` 回搜索框、`PgUp`/`PgDn` 翻页
- 面板高度固定 3 行 —— 条目多少不影响格子位置，肌肉记忆不会因为内容变化而失效
- 点击面板外部、按 `Esc`、再按一次唤出键都能关闭

**不只是快捷方式**
- **文本片段格**：点一下**复制到剪贴板**，然后自己 Ctrl+V。邮箱、地址、签名、
  模板回复、常用代码片段都行，支持多行
- **按键格**：点一下把组合键发给原来的窗口（`Ctrl+Shift+T`、`Alt+Tab`、`F5`、`Win+V`…）
- 文本片段也能**直接打到光标处**：右键格子 →「发送到当前光标处」。
  这条路径不碰剪贴板（走 `SendInput` + `KEYEVENTF_UNICODE` 逐字符发），
  但它依赖把焦点交回原窗口，不是所有场合都成立，所以没做成默认

**动作页**
- 多页面板：腰栏上是**文字页签**（`常用 │ 系统工具 │ …`），点一下就切页，
  点页名打开「动作页」菜单。页数多时页签可横向滚动 —— 之前是 8px 圆点，没有标签只能盲翻
- **滚轮翻页**（内容超出可视区时先滚动，滚到边界才翻页；搜索时滚轮只滚动结果）
- **上下文自动切换**：按当前前台程序切到对应的「场景」页。
  默认内置了 `explorer` 场景，在资源管理器里唤出面板会先看到「下载 / 桌面 / 文档 / 图片 / 此电脑 / 回收站」
- **动作页管理**（点页名，或右键面板空白处 →「动作页」子菜单）：
  新建全局面板页 · 为当前前台程序新建场景页 · 重命名 · 删除 · 在全局与场景之间移动。
  不用再手改 `config.json`
- **搜索跨页**：输入关键词会搜全部已解析的动作页，不用先翻页
- **搜索结果排序**：按「匹配度 → 使用频次 → 最近使用」排序。
  空查询时网格顺序**一动不动** —— 按频次重排会让练出来的肌肉记忆失效
- **格子拖拽排序**：按住格子拖到目标位置松手即可调整顺序，落位处会显示一条蓝色插入指示条。
  拖到列表上下边缘会自动滚动；松手位置在格子区域之外时视为「移到末尾」
- **格子跨页拖拽**：一开始拖拽，整条腰栏就变成页签区（`移到：常用 │ 系统工具 │ …`），
  拖到某个页签上就把这个格子搬到那一页。页数多时页签可横向滚动

**添加条目**
- **从开始菜单批量导入**：右键面板空白处 →「从开始菜单批量导入…」。
  扫描开始菜单（所有用户 + 当前用户）和桌面上的 `.lnk` / `.url`，可过滤、可全选/反选，
  勾选后一次性导入当前动作页
- 把文件 / 文件夹拖进面板（需要先点「钉住」，否则面板会因失焦而隐藏）
- **点面板末行的虚线「＋ 添加」格**：常驻在第一个空槽位上，
  把「怎么加东西」变成看得见的答案 —— 之前只能靠拖文件或者去右键菜单里找
- 右键面板空白处 → 添加文件 / 添加文件夹 / 添加网址
  / **添加文本片段…** / **添加按键组合…**
- 右键托盘图标 → 打开面板 / 设置 / 打开数据目录 / 退出

**管理条目**（右键格子）
- 打开 / 以管理员身份运行 / 打开所在位置 / 复制路径 / 重命名 / 移除
- 文本片段和按键的菜单是另一套：发送到光标处 / 复制内容 / **编辑内容…** / 重命名 / 移除。
  给它们「打开所在位置」没有意义，那只会打开数据目录
- **拖动格子调整顺序**；拖到腰栏的页签上则把这个格子搬到那一页
  （搜索状态下两种拖拽都禁用 —— 那时网格里装的是跨页排序结果，顺序是算出来的，重排没有意义）

**多选与批量操作**（搜索状态下不可用）
- `Ctrl+点击` 加减选中，`Shift+点击` 从锚点连选，`Ctrl+A` 全选当前页，
  点面板空白处或 `Esc` 取消选择
- 选中后状态栏变成「已选 N 项」，右键格子换成批量菜单：
  批量移除 · 批量移到某一页 · 复制多个路径 · 取消选择
- **拖动任意一个选中的格子 = 整组一起搬**（页内调序，或拖到腰栏页签上换页）
- 直接按 `Delete` 也能批量移除
- 拖一个**没被选中**的格子时只拖它自己，并清掉原来的选择 —— 跟资源管理器一致

**其它**
- 搜索框模糊过滤（子序列匹配，`wjll` 能命中「文件浏览器」）
- 「钉住」面板：连续启动多个程序时面板不自动隐藏
- 配置持久化到 `%AppData%\QuickerLite\config.json`，可以直接手改
- 图标磁盘缓存到 `%AppData%\QuickerLite\icons\`
- 单实例：重复启动会唤出已有实例的面板，而不是开第二个进程
- 开机自启（写 `HKCU\...\Run`，不需要管理员权限）

## 快速开始

```cmd
build.cmd              :: 编译 Debug
build.cmd Release      :: 编译 Release
build.cmd Release run  :: 编译 Release 并启动
run.cmd                :: 启动 Debug 版
publish.cmd            :: 打包成不依赖 .NET 运行时的独立 exe（输出到 dist\）
```

编译产物会同步复制到仓库根的 **`release\`**，不用再去 `bin\` 里翻三层：

```
release\QuickerLite.exe                  <- build 的产出，需要本机装 .NET 8 运行时
release\selfcontained\QuickerLite.exe    <- publish 的产出，单文件 ~70MB，拷到哪台机器都能跑
```

POSIX shell（Git Bash / MSYS）下用：

```bash
./build.sh              # 编译 Debug
./build.sh Release      # 编译 Release
./dev-run.sh 8 Debug    # 启动 8 秒、打印新增日志、然后结束进程
./publish.sh            # 打包自包含单文件版到 dist/
./test.sh               # 跑 TileReorder 的 30 条回归断言（失败时退出码非 0）
```

`publish.sh` 不是 `publish.cmd` 的重复劳动：这台机器上 `cmd.exe` 被安全策略挡掉，
`cmd //c` 又会被 MSYS 改写参数退化成交互式 shell，所以 `publish.cmd` 在 bash 里根本跑不到。

启动后：
1. 托盘出现一个蓝色闪电图标
2. 按 **`Ctrl+Alt+Q`**，或者**单击一下 `Ctrl`**，唤出面板
3. 右键面板空白处 → 「添加文件...」加几个自己的程序试试

退出：右键托盘图标 → 退出。

### 唤出方式

| 操作 | 说明 |
|---|---|
| `Ctrl+Alt+Q` | 全局热键，`RegisterHotKey` 注册，最可靠 |
| 单击 `Ctrl` | 按下后 400ms 内松开，期间没碰别的键 / 没点鼠标 / 没滚轮 |
| 单击鼠标中键 | 会吞掉中键事件，浏览器里不再触发「自动滚动」 |

后两种需要安装全局输入钩子（`SetWindowsHookEx`），可以在设置里单独关闭。
**两个都关掉时钩子会被主动卸载** —— 没必要的全局钩子只会白白招杀软。

### 面板快捷键

| 操作 | 按键 |
|---|---|
| 移动键盘焦点 | 方向键（网格内上下左右移动，会自动滚动到可视区） |
| 运行焦点格 | `Enter` —— 注意是**焦点格**不是第一项，配合方向键用 |
| 直接运行第 N 格 | `Ctrl+1` … `Ctrl+9`（前 9 格左上角有数字角标） |
| 回到搜索框 | `Ctrl+F` |
| 上一页 / 下一页 | 滚轮上 / 下、或 `PgUp` / `PgDn` |
| 跳到指定页 | 点腰栏的文字页签 |
| 调整格子顺序 | 按住格子拖动（搜索状态下不可用） |
| 加减选中 | `Ctrl+点击` |
| 连选 | `Shift+点击` |
| 全选当前页 | `Ctrl+A`（搜索框为空时） |
| 批量移除选中 | `Delete` |
| 整组搬移 | 拖动任意一个选中的格子 |
| 关闭面板 | `Esc`（有选中时先取消选择，再按一次才收起） |

搜索框有内容时，左右方向键留给文本编辑，只有上下键移动焦点。

## 已经处理掉的 Windows 平台坑

这些是这类工具真正的工作量所在，代码里都有对应注释。

| # | 坑 | 处理方式 | 代码位置 |
|---|---|---|---|
| 1 | **前台焦点锁** —— 后台进程调 `SetForegroundWindow` 会静默失败，热键唤出的面板拿不到键盘焦点 | 临时 `AttachThreadInput` 到当前前台窗口的线程，再 `SetForegroundWindow`，然后立刻 detach | `PanelWindow.ForceForeground()` |
| 2 | **GDI 句柄泄漏** —— `HICON` 用完不释放，单进程句柄涨到 1 万就崩 | 转成 `BitmapSource` 后立刻 `DestroyIcon`；托盘图标 `GetHicon` 后克隆再释放原句柄 | `IconService.Extract()` / `TrayIconFactory.Create()` |
| 3 | **网络路径卡死 UI** —— `SHGetFileInfo` 遇到断开的网络共享会同步等待超时（最长几十秒） | 图标提取全部跑在独立的 STA 工作线程上；文件夹用 `SHGFI_USEFILEATTRIBUTES` 直接返回通用图标，不访问磁盘 | `IconService` |
| 4 | **`.lnk` / `.url` 打不开** —— `UseShellExecute = false` 时会被当二进制执行 | 统一 `UseShellExecute = true`，让 Shell 做文件关联解析 | `ShellLauncher.Launch()` |
| 5 | **热键注册静默失败** —— 组合键被别的软件占用时只返回 `false`，不报错 | 把失败原因（含 Win32 错误码 1409 = 已被占用）带出来，用托盘气泡提示用户去改 | `HotkeyService.Register()` / `App.RegisterHotkey()` |
| 6 | **低级钩子被误报** —— 全局键鼠钩子是键盘记录器的标准技术，杀软会重点关照 | 无法根治。只能做到：不需要时主动卸载钩子、安装失败时明确提示 | `InputHookService.Apply()` |
| 7 | **多屏 + 高 DPI 坐标错乱** —— 物理像素和 WPF 逻辑单位在混合缩放比下对不上 | 用 `GetCursorPos` + `Screen.FromPoint` 拿物理坐标，`SetWindowPos` 直接按物理像素摆放，绕开 WPF 的单位换算；`app.manifest` 声明 `PerMonitorV2` | `PanelWindow.PositionAtCursor()` |
| 8 | **单实例** —— 双开会导致两套托盘、热键注册冲突、配置互相覆盖 | 命名 `Mutex` 检测；第二个实例通过命名管道通知第一个实例唤出面板后自己退出 | `SingleInstance.cs` |
| 9 | **开始菜单的本地化目录联接** —— 中文版 Windows 的开始菜单里同时存在「程序」和「Programs」，后者是前者指向的目标（`程序` 是个 junction）。按路径字符串去重挡不住它，两个路径长得完全不一样却指向同一批文件，结果是每个快捷方式被扫出两遍（实测 200 → 353） | 按目录的「真实身份」去重：`DirectoryInfo.ResolveLinkTarget(returnFinalTarget: true)` 把 junction 解析到最终目标，普通目录用自身 `FullName`。联接解析出来的正好是被指向目录的 `FullName`，所以能撞上 | `ShortcutScanner.RealPathOf()` |

### 低级输入钩子的五个专属坑

做「单击 Ctrl 唤出」时踩到的，全部集中在 `Core/InputHookService.cs`：

| # | 坑 | 后果 | 处理方式 |
|---|---|---|---|
| A | **委托被 GC 回收** —— `SetWindowsHookEx` 收的是函数指针，CLR 不知道原生侧还引用着它 | 运行几分钟后 GC 一跑，系统回调到已释放的地址：钩子失效，严重时整机输入卡死 | 委托存成字段（`_keyboardProc` / `_mouseProc`），永不改成局部变量 |
| B | **回调超时** —— `LowLevelHooksTimeout` 默认 300ms，超时系统会**静默**摘掉钩子，不报错不通知 | 用着用着唤出就失灵了，且毫无线索 | 回调里只做纯内存判断，真正的活儿 `Dispatcher.BeginInvoke` 推到消息队列之后 |
| C | **自触发死循环** —— 钩子收到系统里**所有**输入，包括自己模拟的 | 一旦将来加了「模拟按键」功能就会无限递归 | 靠 `LLKHF_INJECTED` / `LLMHF_INJECTED` 标志位把注入事件放行 |
| D | **钩子线程** —— 回调运行在「安装钩子的线程」上 | 在 UI 线程安装 → 回调也走 UI 线程，不需要 Marshal，但回调里做的事会卡住消息泵 | 在 UI 线程构造 `InputHookService`，并遵守坑 B |
| E | **误判** —— 难点不是识别 Ctrl，而是排除「按着 Ctrl 干别的事」 | 面板乱弹，用户想砸键盘 | 见下表 |

「按着 Ctrl 干别的事」目前排除了这五种，少任何一种都会被投诉：

| 场景 | 判定依据 |
|---|---|
| `Ctrl+C` / `Ctrl+V` / `Ctrl+Shift` | Ctrl 按住期间有别的**键**按下 → 标记 |
| `Ctrl+左键`多选文件 | Ctrl 按住期间有**鼠标点击** → 标记 |
| `Ctrl+滚轮`缩放 | Ctrl 按住期间有**滚轮** → 标记 |
| 先按住 `Shift` 再点 `Ctrl` | 松开 Ctrl 时 `GetKeyState` 发现别的修饰键还按着 → 不算 |
| 长时间按住 Ctrl 当修饰键用 | 超出判定时间窗（默认 400ms，可调 150–800ms） |

另外还处理了几个 C# / WPF 特有的坑：

- **`Deactivated` 误触发**：打开右键菜单或弹对话框时面板会失活，如果不抑制，「点自己的菜单面板就消失」。用 `_suppressDeactivate` 计数解决。
- **`AllowsTransparency` 会禁用硬件加速**：所以没用它做圆角窗口，改用 Win11 的 DWM 圆角（`DWMWA_WINDOW_CORNER_PREFERENCE`），保持硬件加速。
- **模型类不能叫 `Page`**：`System.Windows.Controls.Page` 已经占了这个名字，撞名后每个 UI 文件都要写别名。改叫 `ActionPage`。
- **`System.Text.Json` 反序列化 `Dictionary` 会丢掉比较器**：构造时传的 `OrdinalIgnoreCase` 不会被保留，`"Chrome"` 和 `"chrome"` 会变成两个场景。`ConfigStore.Normalize()` 里重建一次。
- **内部拖拽和「拖文件进面板」会互相打架**：窗口级的 `AllowDrop` 只认 `FileDrop`，格子拖拽一进来就被判成「不支持的格式」—— 光标变成禁止符号，拖文件用的提示遮罩还会误亮。用自定义剪贴板格式 `QuickerLite.Tile` 把两者区分开，并在格子区域的处理器里 `e.Handled = true` 把事件截住，不让它冒泡到窗口级。

### 拖拽排序的下标数学

「松手应该插到第几位」这段逻辑抽在 `Core/TileReorder.cs` 里，是纯函数，可以脱离界面验证。
两个地方最容易错，都写了注释：

- **行定位不能只按最近距离**。面板是 `WrapPanel` 换行网格，只按距离算的话，
  在行尾的空白处松手会插到上一行去。正确做法是先按 Y 定位到行，再在行内按水平中线比较。
- **往右拖时目标下标要减一**。被拖的格子会先被摘出去，它后面所有元素的下标都会前移一位。
  漏掉这一步的表现是「往右拖一格没反应，拖两格才动一格」。

这段逻辑有 75 条断言覆盖，分两组：拖拽下标 44 条、按键解析 31 条
（行边界、网格外的上下方、空列表、往左/往右/原地不动、
只有一格、下标越界，以及多选时的连续块 / 不连续选区 / 全选 / 单选走块路径 / 越界）。
跑 `./test.sh` 即可，改动这段逻辑时建议重新跑一遍。

### 跨页搬移为什么用「腰栏变页签」而不是让 `‹` `›` 接住

最省事的做法是让 `‹` / `›` 按钮接住拖拽（拖到 `‹` 就是移到上一页）。但那只能盲翻 ——
你看不见目标页叫什么，要跨好几页就得拖好几次。

所以选的是：**拖拽一开始，整条腰栏就让位给页签区**（`移到：常用 │ 系统工具 │ …`）。
当前页也在页签里（拖上去会提示「已经在里面了」，比把它藏起来更好理解），
页签多了可以横向滚动。腰栏在拖拽这一刻的职责只剩「当放置区」，
所以状态文字和「钉住 / 设置」暂时让位，拖完立刻恢复。

两个实现上的细节：窗口级的 `AllowDrop` 会把「拖到腰栏空白处」当成「移到末尾」，
必须由腰栏自己截住（`e.Handled = true`）；而「落位回调」和「拖拽结束」都会调一次恢复，
不加门闩的话第二次会把刚设好的「已移到…」提示冲掉。

### 界面令牌的唯一来源放在 C#，不在 XAML

`UI/DesignTokens.cs` 里定义 `Palette`（色阶）和 `Metrics`（尺寸）两个静态类，
`Themes/Tokens.xaml` 的样式通过 `{x:Static ui:Palette.Accent500}` 引用它们。

反过来做（色值写在 XAML 资源里）看起来更「WPF」，但会出一个实际问题：
**C# 里凡是要在代码里建控件的场合**（页签、拖拽页签、右键菜单），就得把同一个色值再抄一遍。
抄两遍的东西必然漂移，而且漂移是静默的 —— 界面上只是「两个蓝色不太一样」，没人会提 bug。
放 C# 里则只有一份定义，XAML 反向引用。`x:Static` 还是**编译时**检查的，
写错属性名构建就失败；相比之下 `StaticResource` 的键名拼错要到运行时炸。

代价是 XAML 里要引 `xmlns:ui`，以及「改颜色要重新编译」——对这个项目无所谓。

### 面板高度固定 3 行

之前是 `SizeToContent="Height"`，8 个条目和 16 个条目弹出来的面板不一样高。
更糟的是面板靠近屏幕底部时会整体翻到光标上方，两种情况下格子的绝对位置完全不同 ——
而肌肉记忆建立在「第 3 格永远在这个位置」上，位置会变，记忆就废了。

现在高度按 `行数 × 行高 + HeaderHeight + FooterHeight` 直接算死。
Header / Footer 的高度是常量（按 XAML 的 Margin 手算），所以启动时会做一次几何自检：
`面板几何：期望 578×392，实际 578×392`。**常量推导错了这行就会不一致**，
比「看着差不多」可靠得多。

### 阴影不要开 `AllowsTransparency`

想要浮层投影，第一反应是 `AllowsTransparency="True"` + 自绘阴影。
在 WPF 上这会**让整个窗口退回软件渲染**，而面板是热键高频唤出的，掉帧和拖动闪烁立刻可见。

正确做法是保持 `AllowsTransparency="False"`，改用
`DwmExtendFrameIntoClientArea` 把四条边各扩展 1px 交给 DWM 画系统投影。
代价是阴影样式由系统决定，不能自定义 —— 这个交换是划算的。

### 键盘焦点不能抢 WPF 的焦点

格子按钮是 `Focusable="False"`，这是对的：焦点必须留在搜索框，否则打字会断。
所以「方向键选中的格子」是**自己维护的一套状态** —— 视图模型上的 `IsFocusCursor`
加窗口里的 `_focusIndex`，跟 WPF 的焦点系统完全无关。

这样「打字过滤」和「方向键选格子」才能共存：过滤改变 `_view` 的内容，
方向键改的是 `_focusIndex`，两者互不干扰。

### 文本片段为什么默认复制到剪贴板

一开始做的是「点一下直接打到光标处」，实测下来**不可靠**，所以默认改成了复制。

根因是下面那条焦点顺序。这里补一句更根本的：`SendInput` 的返回值只表示
「事件有没有被插入输入队列」，**不代表它发到了你想发的窗口**。所以失败是完全静默的 ——
日志里 `UseCount` 还在涨，看起来一切正常，文字却出现在了别的窗口，或者哪儿都没有。

复制到剪贴板则没有这个不确定性：永远成功，粘到哪、什么时候粘由用户决定。
代价是多一次 `Ctrl+V`，换来的是可预期 —— 对一个「点了就得有反应」的东西，
这个交换是值的。

想要直打的话，右键菜单里还留着「发送到当前光标处」。

### 交还焦点的顺序：先交后藏，反了就是静默失败

`SetForegroundWindow` 只在**调用方自己还是前台进程**时被系统接受。

所以顺序必须是：

1. 面板**还可见**（也就是本进程还是前台进程）时，先 `SetForegroundWindow(原窗口)`
2. 轮询等 `GetForegroundWindow()` 真的等于目标，最多 500ms
3. **然后**才 `HidePanel()` —— 此时面板已经不是前台，藏它不会把焦点抢回来
4. 发送

我第一版写反了：先 `HidePanel()` 再 `SetForegroundWindow`。面板一藏，
本进程立刻失去前台身份，这个调用被系统**直接拒绝** —— 返回 `false`，
不抛异常、不打日志。于是焦点落到某个随机窗口，内容全打飞。

两个配套的细节：原窗口句柄要在 `Show()` **之前**抓（一旦显示，前台就是我们自己了）；
等待用轮询而不是固定延时，因为不同机器、不同目标程序的恢复速度差别很大。

这类 bug 的恶劣之处在于**所有返回值都看着正常**：`SendInput` 报成功、
`UseCount` 照涨、没有异常。唯一能抓住它的只有「用户的眼睛」。

## 已知限制

- **中键会被吞掉**。为了避免浏览器弹出「自动滚动」，中键的 down/up 都被钩子拦下了。副作用是中键拖拽、中键粘贴（终端里）也会失效。不需要的话在设置里关掉。
- **拖拽添加需要先「钉住」**。因为从资源管理器开始拖拽时，面板会因为失去焦点而隐藏。点一下面板底部的「钉住」再拖即可。
- **搜索状态下不能拖拽、也不能多选**。搜索结果跨页混排，顺序是算出来的，
  「选中的是哪几个」会随输入变化，没有稳定含义。
- **多选只能 Ctrl / Shift 点击，不支持框选**（从空白处拖出一个矩形）。面板是换行网格，
  框选要处理跨行和边缘自动滚动，性价比不高，先不做。
- **多选只在当前页内有效**，不能跨页选中。
- **跨页搬移不会跟着跳页**，格子搬走后你仍停在原来的页，方便连续往外挑。
- **导入列表不显示图标**。200 个快捷方式逐个 `SHGetFileInfo`，只要有一个指向断开的网络共享就会阻塞图标线程几十秒。导入进面板之后图标才异步补上。
- **导入不解析 `.lnk` 的目标路径**。面板里存的是 `.lnk` 本身，所以「打开所在位置」会定位到开始菜单目录，而不是程序安装目录。
- **识别不了没建开始菜单快捷方式的软件**。只扫开始菜单和桌面，不读注册表 `Uninstall` 项。
- **「发送到当前光标处」（右键菜单里那条）不是所有场合都成**。它要先把焦点交回原窗口，
  而前台调度是系统在管，做不到 100%。另外 `KEYEVENTF_UNICODE` 依赖目标程序处理
  `WM_UNICODE_CHAR`，个别老程序、以及以管理员权限运行的窗口（UIPI 会拦掉模拟输入）收不到。
  这也是为什么默认动作是复制而不是直打。
- **点文本片段会覆盖剪贴板**。这是它的工作方式和「不碰剪贴板」的那条路径正好相反 ——
  选哪条取决于你要不要保住当前剪贴板内容。
- **不支持标点符号键**（`Ctrl+;` 之类）。字母、数字、`F1`-`F24` 和一批命名键够用了，
  标点要维护一张容易出错的 OEM 键码表，性价比不划算。
- **图标缓存不会自动清理**。删掉 `%AppData%\QuickerLite\icons\` 即可重建。
- **开机自启建议用独立发布版**。Debug 版依赖机器上 .NET 运行时的位置，如果 SDK 装在非标准目录，开机时会报 `Failed to resolve hostfxr.dll`。用 `publish.cmd` / `publish.sh` 生成的自包含版本没有这个问题。
- **没有代码签名**。自包含发布的 exe 首次运行会被 SmartScreen 拦一下（「更多信息」→「仍要运行」）。这也是全局钩子被误报的放大器。

## 配置结构

`%AppData%\QuickerLite\config.json`：

```jsonc
{
  "Columns": 6,
  "Hotkey": { "Modifiers": 3, "VirtualKey": 81, "Display": "Ctrl+Alt+Q" },
  "StartWithWindows": false,

  // 唤出方式
  "EnableSingleCtrl": true,       // 单击 Ctrl 唤出
  "EnableMiddleClick": true,      // 单击中键唤出
  "SingleCtrlTimeoutMs": 400,     // 单击 Ctrl 判定时间窗（150–800）

  // 全局面板区：不随前台程序变化
  "GlobalPages": [
    { "Name": "常用", "Items": [ /* ActionItem[] */ ] },
    { "Name": "系统工具", "Items": [ /* ... */ ] }
  ],

  // 上下文场景：前台进程名（小写、不含 .exe）→ 该程序专用的动作页
  "Scenes": {
    "explorer": [ { "Name": "资源管理器", "Items": [ /* ... */ ] } ]
  }
}
```

格子顺序就是 `Items` 数组的顺序，拖拽排序改的也是它 —— 想手工调整顺序，直接改这个数组也行。
想恢复初始内容，删掉 `config.json` 重启即可（会自动重建为 2 个全局页 + 1 个 `explorer` 场景）。
旧版只有扁平 `Items` 的配置会在启动时自动迁移到「默认」页，并立刻写回新格式。

## 下一步可以做什么

按「每天会碰到的摩擦」排序，不是按功能完整性 —— 框选、一键排序这类
每月才用一次的东西，不该排在「加东西还要手工拖」前面：

1. **读注册表 `Uninstall` 项补充软件列表** —— 有些软件装了不建开始菜单快捷方式。
   这是「每天都会碰到的摩擦」，优先级高于下面几项
2. **选中文本的上下文动作** —— 唤出时抓当前选中的文字，动作里能用 `{selected}` 占位符。
   有了它，文本片段能升级成「处理选中文本」。成本比第 1 项高，但价值也高
3. **多选框选** —— 从空白处拖出一个矩形批量选中，现在只能 Ctrl / Shift 一个个点
4. **按名称 / 使用频次一键排序当前页** —— 拖拽之外再给个省事的入口
5. **导入列表延迟加载图标** —— 只给可视行提图标（`ItemContainerGenerator` + `ScrollChanged`），
   兼顾辨识度和「绝不碰网络路径」这两件事
6. **组合动作 / 脚本引擎** —— Quicker 真正的护城河，也是个无底洞。
   做了等于开始养第二个产品，自用的话投入产出比很低
7. **深色主题** —— 整套色阶要重算 + 对比度全部复验，工作量约等于把界面那轮再做一遍，
   要做得单独立项

## 关于构建环境

`build.cmd` / `build.sh` 开头补了几个 Windows 环境变量（`ProgramData`、`APPDATA`、
`ProgramFiles` 等）。这不是多余的：NuGet 直接用这些变量去定位配置文件目录，
在精简环境（容器、CI、最小化 shell）里它们可能是空的，此时 NuGet 会抛出一个
**完全看不出原因**的错误：

```
error : Value cannot be null. (Parameter 'path1')
```

补上变量即可。如果你在正常的 Windows 桌面上构建，这些判断不会生效。

另外，如果 .NET SDK 装在非标准位置（比如用户目录下的便携安装），
启动编译好的 exe 需要设置 `DOTNET_ROOT`，否则 apphost 会报
`Failed to resolve hostfxr.dll [error 0x80008083]`。`run.cmd` / `dev-run.sh` 里已经处理。

`build.sh` / `publish.sh` 里还有两处环境相关的细节，改之前先看一眼注释：

- **项目路径要用 `cygpath -w` 转成 Windows 形式**。这个 shell 带着
  `MSYS_NO_PATHCONV=1` 和 `MSYS2_ARG_CONV_EXCL=*` 运行，MSYS 不会帮你把
  `/d/projects/...` 转成 `D:\projects\...`，而 MSBuild 会把 `/d/...` 当成未知开关，
  报一个很误导的 `error MSB1001: 未知开关`。
- **`ProgramFiles(x86)` 只能通过 `env` 注入**。bash 的 `export` 不接受带括号的变量名。
